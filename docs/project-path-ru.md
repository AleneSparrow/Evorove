## 1. Идея и движок — «нам написали»

**11–13 августа 2026.** Рабочее имя Atelier, затем AI Business Process Engine.

Наблюдение: бизнесу не нужен ещё один чат. Нужен процесс, который не теряет человека между сообщением и следующим шагом.

Что сделала:

- карта полного пути: лид → квалификация → запись или смета → follow-up → сделка → оплата;
- универсальный процесс отдельно от правил бизнеса (**Business DNA**);
- состояния, журнал событий, PostgreSQL, идемпотентность, мультитенантность;
- AI понимает язык и формулирует ход, решения бизнеса не принимает;
- первый живой срез: входящее сообщение → лид и кейс;
- виджет на сайте + кабинет сотрудников.

Макеты того месяца, не подключённые к API: [`archive/front/`](../archive/front/).
Спека, архитектура и README того этапа: [`archive/inbound-engine-2026-08/`](../archive/inbound-engine-2026-08/).

## 2. Flywheel: кабинет, каналы, деньги

**14–31 августа 2026.** Публичное рабочее имя — Flywheel.

Что сделала:

- ребренд Atelier → Flywheel;
- SMS (Twilio), биллинг (сначала Stripe, затем Lemon Squeezy);
- деплой, CI, кабинет с нескольких бизнесов на один аккаунт;
- UX двух сторон: виджет для клиента и дашборд для владельца;
- возражения только в рамках политики, follow-up с согласием.

## 3. Закрытый цикл и имя Evorove

**3–6 сентября 2026.**

Метрика: разговоров много, записей почти нет. Система собирала имя и телефон и отдавала человека сотруднику. Это был clipboard, не работа.

Default сменили: квалифицированный лид получает следующий шаг — консультацию, визит или демо по времени. Цена по-прежнему не выдумывается.

6 сентября публичное имя — **Evorove**. Движок тот же. Формулировка ещё «входящее обращение → запись». Генерации в открытом поле ещё нет.

Старый указатель сессии (вход → сделка, без генерации): [`archive/claude-md-inbound-lead-engine-2026-09-07.md`](../archive/claude-md-inbound-lead-engine-2026-09-07.md).

## 4. Три цикла

**7–11 сентября 2026.**

Владелец зафиксировала другую основу: не ждать, пока человек сам напишет.

```text
1. Генерация   →  человек найден в открытом поле, с причиной
2. Продажа     →  холодное письмо и разговор до готовности
3. Закрытие    →  продажа или конкретный час
```

Код разрезали по циклам, не по трём сайтам:

| Репозиторий | Цикл | Делает |
| --- | --- | --- |
| `evorove_lead` | 1 | Ищет, кладёт в Cold. Не пишет. |
| `evorove` | 2 | Пишет и продаёт. Не ищет. |
| `evorove-crm` | доска + закрытие | Держит вкладки. Не парсит интернет. |

Срезы A–D (граница продажи, тон, исходящий ход, каркас поиска, корпус companion): [`archive/alignment-2026-09/foundation-alignment-stage-ru.md`](../archive/alignment-2026-09/foundation-alignment-stage-ru.md).

10 сентября обучены локальные LoRA companion. Прод-рот не переключали: loss ≠ eval продажи.

Карта репозиториев того решения: [`three-repos-next-steps-ru.md`](three-repos-next-steps-ru.md).

## 6. Сайт и клиент 0

**Середина сентября — октябрь 2026.**

Сайт и кабинет — [evorove.com](https://evorove.com). API — [api.evorove.com](https://api.evorove.com). Один проект Railway.

Что уже решено в коде этого репозитория: первое письмо с Cold пишет движок; оффер берёт материалы и ссылку оплаты бизнеса; Done — только по записанной оплате или часу, не потому что ссылку показали.

Что ещё делает владелец: выкатить рабочее дерево на домен (пушит только она), прогнать одну живую карточку Cold → письмо → ответ → оффер → Done.

Чеклист переменных без значений: [`client-zero-owner-checklist-ru.md`](client-zero-owner-checklist-ru.md).
